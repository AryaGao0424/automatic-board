# 02 · 技术架构设计

> **文档定位**：技术面核心材料。展示架构分层、技术选型理由、数据流与模块地图。

---

## 2.1 技术选型与理由

| 备选方案 | 对比结论 |
|---|---|
| **Streamlit（选中）** | 纯 Python、交互式看板秒级迭代、`@st.cache_data` 天然缓存，适合单人快速构建数据产品 MVP |
| Power BI / Tableau | 可视化强但需商业授权，难以承载自定义算法（口径②、四维风险分），无法实现"一行代码换数据源" |
| Flask/Django + ECharts | 前后端分离复杂度高、开发成本大，对单人实习项目不现实 |
| 静态 Excel 透视表 | 无法交互联动、口径不可控、没有自动洞察 |

**选型三原则**：快（MVP 导向）、省（零后端，单文件可交付）、活（算法自定义、数据可替换）。

---

## 2.2 总体架构（三层）

```
┌─────────────────────────────────────────────────────────┐
│ ① 数据接入层   3个Excel上传(st.file_uploader) + 读取 + 缓存  │
│   主表(列表) / 金额表(金额) / BIP优化台账(分类明细sheet)      │
└─────────────────────────────────────────────────────────┘
                        ↓ load_and_merge()
┌─────────────────────────────────────────────────────────┐
│ ② 指标计算层   字段标准化 + 指标引擎 + 去重规则              │
│   处理时间→月份/年份 | 作业时长"X分X秒"→秒 | 驳出→is_rejected│
│   退单率(口径②) | 四维风险分 | 可挽回工时 | 标签集中率        │
└─────────────────────────────────────────────────────────┘
                        ↓ 统一标准 DataFrame
┌─────────────────────────────────────────────────────────┐
│ ③ 可视化展示层   Streamlit 布局 + Matplotlib 渲染           │
│   9大模块联动（全局筛选器生效） | 状态高亮 | 交互明细表       │
└─────────────────────────────────────────────────────────┘
```

**架构核心设计：数据与展示分离**。所有图表只消费标准格式的 DataFrame；替换数据源只需修改 `load_and_merge()` 一处，因此可低成本复用到费用组、资产组等其他业务线。

---

## 2.3 数据流全景

```
用户上传3个Excel
   ↓
load_and_merge()：主表 × 金额表（金额先按单据编号聚合求和）→ left join
   ↓
衍生列：金额(元/万元) / 月份 / 年份 / 作业时长_秒 / is_rejected
   ↓
侧边栏筛选：月份 × 处理人 × 作业状态 × 交易类型
   ↓
df（筛选后全集，各模块共享同一数据源）
   ├── KPI引擎        → 5 张指标卡片 + 智能业务洞察
   ├── 图表1+2        → 三大核心原因月度趋势 + 痛点结构占比
   ├── 图表3          → 委托单位 Top20 双图（体量 + 质量）+ 15% 红线
   ├── 体检报告       → Top3 四维风险分 + 环形图 + 自动评级 + 督办令
   ├── 多维度专项     → 处理人 / 交易类型 / 重复退单 / 来源系统 / 制单人Top15
   ├── BIP 攻坚台账   → 3KPI + 未推进Top + 状态筛选 + 明细高亮
   └── 底部明细表     → 全字段预览 + 状态高亮 + 行数滑块
```

| 来源系统 | 财务会计 / 费控服务 | 来源系统对比 |
| 制单人 / 制单人编码 | 前端制单人身份 | 制单人 Top15 |

| 字段 | 说明 |
|---|---|
| 单据编号 | 与主表关联键 |
| 金额 | 按单据编号 groupby 求和（避免 1:N 行数膨胀） |

### BIP 优化台账 `BIP应付组系统优化点_分类汇总.xlsx`（读取"分类明细"sheet）

| 字段 | 说明 |
|---|---|
| 序号 / BIP系统模块 / BIP系统优化点 | 需求主体 |
| 状态 | 已完成 / 进行中 / 待评估 / 关闭需求 |
| 一级分类 / 二级分类 | 分类统计 |
| 解决方案 | 应对措施 |

### 衍生列字典（代码中生成）

| 衍生列 | 来源 | 计算逻辑 | 用途 |
|---|---|---|---|
| 金额（元） | 金额表 | groupby(单据编号).sum() | 合并后金额 |
| 金额（万元） | 衍生 | 金额(元)/10000 | 展示口径 |
| 处理时间_dt | 主表 | pd.to_datetime(errors="coerce") | 时间解析 |
| 月份 / 年份 | 衍生 | dt.month / dt.year | 趋势与筛选 |
| 作业时长_秒 | 主表 | 正则解析"X分X秒"，"--"视为0 | 工时统计 |
| is_rejected | 主表 | 驳出共享次数≥1 | 口径②退单标记 |

## 2.6 关键工程设计

1. **数据与展示分离**：图表只认标准 DataFrame，换数据源改一处；
2. **双表合并防膨胀**：金额表先聚合再 join，避免 1:N 行数爆炸（这是真实数据最常见的坑）；
3. **缓存设计**：`@st.cache_data` 按文件内容哈希缓存，重复交互零 IO；
4. **中文字体多候选回退**：SimHei → Microsoft YaHei → STHeiti → WenQuanYi，逐个尝试可用即停，解决 matplotlib 中文乱码；
5. **文本鲁棒性**：统一兜底 `--` / `nan` / 空值 / 非规范"X分X秒"；
6. **动态文案生成**：督办令按痛点异同分支生成，而非固定模板；
7. **辅助列隐藏**：底部明细表剔除 6 个衍生辅助列，避免业务同事困惑。

## 2.7 可复用与扩展设计

- 虚拟→真实字段映射表（见 `..\架构设计v2.0.docx`）验证了"数据源可一行切换"；
- 通用 DataFrame 接口 → 费用组/资产组复用只需替换数据源 + 调整业务字段名；
- BIP 台账为**可选数据源**（未上传不影响主流程），模块间低耦合；
- 未来扩展：接 BIP API 实时数据、多组模板化复用、简易访问控制。

---

## 2.8 面试怎么讲

- **讲选型**：突出"为什么不用成熟 BI"——算法自定义与可复用性是刚需；
- **讲架构**：用比喻——"所有图表只认标准格式的菜谱（DataFrame），换食材（数据源）不用换锅"；
- **讲模块**：9 大模块按"总览 → 趋势 → 病灶 → 处方 → 闭环"组织，体现产品思维。
