## 7.3 关键函数导读

### `load_and_merge(main_bytes, amount_bytes)` — 数据接入核心

```python
@st.cache_data
def load_and_merge(main_bytes, amount_bytes):
    df_main  = pd.read_excel(main_bytes, sheet_name=0)
    df_amount = pd.read_excel(amount_bytes, sheet_name=0)
    # 金额表先按单据编号聚合求和，避免 1:N 行数膨胀
    df_amt_agg = df_amount.groupby("单据编号", as_index=False)["金额"].sum()
    df = df_main.merge(df_amt_agg, on="单据编号", how="left")
    ... # 衍生列：金额(万元)/月份/年份/作业时长_秒/is_rejected
```

**设计要点**：① 金额表先聚合再 join；② `@st.cache_data` 按文件内容缓存；③ 一次函数完成"读取 + 聚合 + 合并 + 衍生"，职责内聚。

### `parse_duration_seconds(s)` — 文本解析鲁棒性

```python
def parse_duration_seconds(s):
    """解析 'X分X秒' 为秒数；'--' 视为 0 秒；空值返回 None"""
    m = re.match(r"(?:(\d+)分)?(\d+)秒", s)
    return mins*60 + secs if m else None
```

真实业务数据中"X分X秒""--"""混存，正则 + 兜底逻辑保证不报错。

### `is_rejected_flag(x)` — 口径②判定

```python
def is_rejected_flag(x):
    s = str(x).strip()
    if s in ("--", "nan", "0", ""): return False
    return int(float(s)) >= 1   # 驳出共享次数 ≥ 1
```

兼容文本/数值混存的脏数据。

### `load_bip_issues(bip_bytes)` — 独立数据源

读取 BIP 优化台账"分类明细"sheet，独立于主流程，未上传时其余模块照常运行（低耦合）。

## 7.4 一条数据的完整旅程（可面试口述）

1. 用户在侧边栏上传主表 + 金额表；
2. `load_and_merge()`：金额按单号聚合 → left join → 派生 月份/年份/作业时长_秒/is_rejected/金额(万元)；
3. 侧边栏筛选器作用于 `df_all` → 得到筛选后 `df`；
4. KPI 引擎：`df_unique_all`（分母 7522）vs `df_rejected_unique`（分子 465）→ 退单率 6.2%；
5. 各模块消费同一个 `df`：分组 → 聚合 → 排序 → 绘图；
6. 底部明细表展示全字段，审核驳回/通过分别红/绿高亮。

## 7.5 工程实践亮点

- **纯函数 + 缓存**：无副作用、可缓存、可单测；
- **防御式编程**：`--`/`nan`/空值/非规范格式统一兜底；
- **单文件可交付**：双击 bat 即可运行，降低业务同事使用门槛；
- **生成式文档**：`generate_guide.py` 依据代码自动生成使用指南，文档与代码永不脱节；
- **迭代管理**：备份旧版 + PDF 快照 + 演示 webm，版本可回溯、可佐证。

---

## 7.6 代码可改进方向（面试"项目还能怎么改进"就答这个）

1. **单文件过大（1,435 行）** → 按 `data/` `metrics/` `charts/` 拆分或包结构；
2. **魔法数字**（15% 红线、四维权重）→ 提炼到配置类或 YAML；
3. **缺单元测试** → 对口径②、去重规则、正则解析补充 pytest 用例；
4. **数据源依赖 Excel** → 预留 API / SQL 接口（架构已支持，一行切换）；
5. **无登录鉴权** → 企业内部可加简易访问控制；
6. **图表性能** → 数据量增大时可引入 Plotly 或缓存聚合结果。
